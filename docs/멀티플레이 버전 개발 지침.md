"완전한 멀티플레이 기능"을 처음부터 다 만들 필요는 없지만, "데이터 구조와 객체 설계"는 처음부터 멀티플레이 확장을 염두에 두고 뼈대를 잡는 것(Architecture for Network-readiness)이 가장 이상적입니다.  
설계 기초 단계에서 자함(Ownship)과 적함(Target)의 처리 방식을 분리해 버리면, 나중에 멀티플레이를 얹을 때 코드 전체를 뜯어고쳐야 하는 리팩터링 지옥에 빠지기 쉽습니다. 반면 데이터 인터페이스만 깔끔하게 추상화해 두면 싱글 플레이 개발에 전혀 부담을 주지 않으면서도 추후 1\~2일 만에 멀티플레이 레이어를 가볍게 결합할 수 있습니다.

### **1\. 설계 초기부터 반드시 분리해 두어야 할 구조 (Data-Driven Architecture)**

핵심 원칙은 "소나 시뮬레이션 엔진은 플레이어가 누구인지, AI인지 원격 유저인지 알 필요가 없게 만드는 것"입니다.

\[로컬 플레이어 입력\] ──┐  
\[단순 AI 로직\]       ──┼──\> \[Acoustic Entity (위치/속도/RPM/음향출력)\] ──\> \[소나 DSP & 렌더러\]  
\[WebRTC 원격 패킷\]  ──┘

* **엔티티(Acoustic Entity) 추상화:**  
  * 잠수함을 '플레이어 전용 객체'로 하드코딩하지 않고, 자함이든 적 잠수함이든 동일한 AcousticEntity 데이터 구조(위치, 속도, 수심, 엔진 RPM, 캐비테이션 레벨, 방출 주파수 배열)를 갖도록 만듭니다.  
* **센서 엔진의 독립성:**  
  * 소나 연산 파이프라인(WebGPU/AudioWorklet)은 월드에 존재하는 모든 AcousticEntity 목록을 받아 각자 자함 센서와의 거리·각도·전파 손실을 계산해 워터폴과 오디오를 그리기만 하면 됩니다.

### **2\. 추천 개발 순서: 3단계 점진적 빌드업**

* **Step 1: 싱글 플레이 로컬 엔티티 완성 (현재 단계)**  
  * 자함(Local Player)과 목표물(Dummy Target)을 동일한 엔티티 포맷으로 생성합니다.  
  * 목표물은 정해진 경로를 직진하거나 간단한 스크립트로 회두하게 두고, BASS/LOFAR/TMA 및 음향 물리 시스템의 완성도와 재미를 먼저 검증합니다.  
* **Step 2: 상태 데이터 직렬화(Serialize) 확인**  
  * 싱글 플레이가 돌아갈 때, 해당 엔티티의 상태(JSON 또는 Float32Array)를 문자열로 추출하고 다시 복원하는 경량 함수(serialize() / deserialize()) 2개만 미리 만들어 둡니다.  
* **Step 3: WebRTC DataChannel 레이어 연결 (후반부)**  
  * 싱글 플레이의 모든 게임플레이가 완벽해진 시점에, PeerJS 등을 붙여 상대방 엔티티의 deserialize() 함수에 원격 수신 패킷을 밀어 넣어주기만 하면 즉시 1:1 대전 모드가 완성됩니다.

### **3\. 예시 코드 구조 (간단한 인터페이스 분리)**

JavaScript  
// 모든 잠수함/표적이 공유하는 단일 음향 상태 포맷  
class SubmarineEntity {  
  constructor(id) {  
    this.id \= id;  
    this.position \= \[0, \-150, 0\]; // x, depth, z  
    this.heading \= 0;             // 방위각  
    this.speed \= 4.0;             // 노트  
    this.rpm \= 90;  
    this.cavitation \= 0.0;  
    this.tonals \= \[60, 120, 180\]; // LOFAR 주파수  
  }

  // 나중에 네트워크로 보낼 압축 데이터  
  exportState() {  
    return {  
      pos: this.position,  
      hdg: this.heading,  
      spd: this.speed,  
      rpm: this.rpm,  
      cav: this.cavitation  
    };  
  }

  // 네트워크나 AI로부터 상태를 주입받는 통로  
  importState(data) {  
    this.position \= data.pos;  
    this.heading \= data.hdg;  
    this.speed \= data.spd;  
    this.rpm \= data.rpm;  
    this.cavitation \= data.cav;  
  }  
}

이처럼 **"데이터 포맷과 소나 렌더러"만 먼저 깔끔하게 분리해 두고 싱글 플레이 모드에 집중**하여 프로토타입을 빠르게 완성하는 것이 개발 속도와 확장성 측면에서 가장 효과적입니다.
