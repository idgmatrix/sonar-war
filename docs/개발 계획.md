# SSN-X 소나 시뮬레이터 — 개발 계획

> 근거 문서: `근미래 전술 잠수함 소나 시뮬레이터 시스템 설계 명세서.md`, `WebRTC 기반 1_1 멀티플레이 구조.md`, `멀티플레이 버전 개발 지침.md`

## 1. 목표와 원칙

- **플랫폼:** 웹 브라우저 (데스크톱 우선). 별도 게임 서버 없음 — 멀티플레이는 WebRTC P2P.
- **핵심 원칙 (개발 지침 문서):**
  1. 모든 잠수함/표적은 동일한 `AcousticEntity` 데이터 구조. "누가 조종하는지" 엔진은 모른다.
  2. 센서/렌더 파이프라인은 `AcousticEntity[]`만 받는다.
  3. `exportState()` / `importState()`를 **첫날부터** 구현해 둔다.
- **점진 빌드업:** 싱글 플레이 완결 → 직렬화 검증 → WebRTC 결합. 멀티플레이는 후반부(마일스톤 M8)에 얹는다.

## 2. 기술 스택 결정

| 영역 | 선택 | 비고 |
|---|---|---|
| 언어 | **TypeScript** (게임/UI/시뮬레이션) + **Rust** (DSP 코어) | 물리/수학 코드가 많으므로 타입 안전성 필수. DSP는 Rust에서 사실적 음향 생성 |
| 빌드 | **Vite** (TS) + **wasm-pack/cargo** (Rust → WASM) | dev: cargo watch + wasm-pack build 자동화 |
| 시뮬레이션 루프 | 고정 시간 스텝 **10Hz** (렌더는 60fps 보간) | 물리 결정론성 확보, 네트워크 동기화 기준이 됨 |
| 오디오 DSP | **Rust/WASM DSP 코어 (AudioWorklet 호스트) + Web Audio API (보조)** | Rust: 해양 잡음 합성, 엔티티 소음 합성(토널/캐비테이션/DEMON/도플러), **풀 지연-합 빔포밍**. Web Audio: 출력 경로, 사후 필터링(무전기 FX 등), 게인/라우팅만 담당 |
| 소나 디스플레이 | **2D Canvas 먼저, WebGPU 후발** | BASS/LOFAR 워터폴은 스크롤링 이미지라 2D Canvas가 충분하고 반복이 빠름. WebGPU는 PDF 클라우드 셰이더와 성능 병목 발생 시 도입 (명세서 Phase 2 대응) |
| 전술 맵 | 2D Canvas (와이어프레임/등고선) | Three.js 3D 뷰는 마지막 옵션 (명세서의 선체 와이어프레임 뷰) |
| 음성 | Web Speech API + Web Audio 무전기 필터 FX | 코파일럿 (M7) |
| 멀티플레이 | **PeerJS** (DataChannel, `ordered:false, maxRetransmits:0`) | 시그널링은 PeerJS 클라우드 + SDP 복사/붙여넣기 폴백 |
| 테스트 | Vitest (TS) + **cargo test** (Rust) | 음향 물리/DSP 코어는 Rust 네이티브 테스트로 빠르고 정밀하게 검증 (M1~M2) |

**WebGPU 도입 시점 판단 기준:** 2D Canvas 워터폴이 프레임 드롭을 일으킬 때, PDF 클라우드가 셰이더로만 표현 가능한 밀도로 올라갈 때. 그 전에는 Canvas 2D로 간다.

## 4. 핵심 데이터 구조

```ts
// 모든 잠수함/표적/어뢰/미끼가 공유하는 단일 음향 엔티티
interface AcousticEntity {
  id: string;
  kind: 'sub' | 'torpedo' | 'decoy';
  position: [number, number, number];   // x, depth, z (m, 수심은 +down)
  velocity: [number, number, number];
  heading: number;                      // rad
  rpm: number;                          // 스크루 회전수
  cavitation: number;                   // 0~1 광대역 레벨
  tonals: number[];                     // Hz, LOFAR 토널 (기계 고조파)
  bladeRate: number;                    // Hz, DEMON 복조 주파수 (RPM×엽수/60)
  sourceLevels: { broadband: number; tonal: number[] }; // dB
  towedArrayDeployed: boolean;
}

// 네트워크 페이로드 (2~5Hz, 수십 바이트) — WebRTC 문서의 acousticState와 1:1 대응
exportState(): { pos, vel, hdg, spd, rpm, cav, tonals, bladeRate, towed }
importState(data): void
```

- **TL 룩업 그리드:** 맵(해저 지형 + 수온약층)이 정해지는 시나리오 시작 시,
  `(거리 × 발신 수심 × 수신 수심 × 주파수 대역)` 격자로 TL 테이블을 **미리 계산**해 두고
  시뮬레이션 중에는 조회만 한다. 프레임당 레이 트레이싱을 피하는 핵심 최적화.
- **음영 구역:** 같은 그리드에서 전달 불가 영역을 플래그로 저장 → TMA PDF 클라우드에서
  "안개가 깎이는" 영역으로 사용.

## 5. 마일스톤 (각 단계: 작업 + 완료 기준)

### M0 — 스캐폴딩 (1~2일)
- Vite + TS 프로젝트, 위 폴더 구조, `git init`
- **`dsp-core` Rust 크레이트 스캐폴딩**: wasm-pack + cargo watch 개발 루프,
  `process()` 스텁이 WASM으로 브라우저에서 실행되는 것 확인
- 10Hz 고정 틱 루프 + 60fps 렌더 루프 분리
- `AcousticEntity` + `exportState`/`importState` 구현
- HTML 셸 + Classic P31 Green 테마 플레이스홀더
- **완료 기준:** 빈 화면에 시계(틱 카운터)가 10Hz로 뛰고, 엔티티 직렬화 왕복 테스트 통과,
  WASM 스텁이 AudioWorklet에서 호출되어 44.1kHz 정현파가 스피커로 출력됨.

### M1 — 음향 물리 코어 (dsp-core/Rust) (2~4일)
- 소나 방정식: `SNR = SL − TL − (NL − DI)`, `SE = SNR − DT`
- TL: `20log₁₀R + α(f)·R` (Thorp 흡수 근사), TL 룩업 그리드 + 음영 구역 플래그
- NL: Knudsen C₀ 모델(풍속 파라미터) + 함선/강우 옵션
- 수온약층: 깊이-수온 프로파일 → 음속 프로파일(맥켄지 근사) → 그리드 계산
- 전부 `dsp-core` Rust 크레이트에 구현 — DSP와 같은 언어/테스트 체계
- **완료 기준:** `cargo test`로 "거리/수심/주파수별 SNR·SE 값이 수식과 일치",
  "약층 아래 표적이 음영 구역에 들어감에 따라 SE가 임계 이하로 떨어짐" 검증.

### M2 — DSP 엔진 (Rust/WASM + AudioWorklet) (5~7일)
- **dsp-core (Rust):**
  - 해양 배경잡음 합성 (Knudsen 모델, 풍속 스케일)
  - 엔티티 소음 합성: 토널(LOFAR 라인) + 캐비테이션 광대역 + **DEMON 변조**
    (캐비테이션 포락선을 bladeRate로 AM) + 도플러 시프트(상대 속도 기반)
  - **풀 지연-합 빔포밍** (명세서 3.2의 τᵢ = pᵢ·û/c 그대로 구현) —
    Rust/WASM이라 구형 배열의 실시간 풀 지연-합이 가능. 성능 여유 확인 후
    빔 수/채널 수로 튜닝
  - `cargo test`로 물리/음향 연산 검증 (M1의 물리 코어도 이 크레이트에 통합)
- **AudioWorklet 호스트 (TS):** WASM 로드, `Float32Array` 링버퍼로
  입력 파라미터/출력 샘플 교환, worklet 출력 → AudioContext 연결
- Web Audio API는 출력 경로(게인/라우팅/사후 필터)로만 사용
- **완료 기준:** 표적을 거리/수심별로 배치했을 때 LOFAR 토널 + 광대역이 들리고,
  RPM 변화가 들리며, 접근/이탈 시 도플러가 들림. worklet CPU 점유가
  프레임 예산(10ms)의 50% 미만.

### M3 — 소나 디스플레이 (BASS / LOFAR) (3~5일)
- LOFAR: 주파수-시간 스펙트로그램 워터폴 (2D Canvas), 고조파 자(Harmonic Ruler) 오버레이
- BASS: 광대역 레벨-시간/방위 워터폴
- 빔 조향 UI: 방위/앙각 커서 드래그 → 해당 빔의 신호만 표시
- **완료 기준:** 조향 커서를 맞출 때만 토널이 선명해지고, 고조파 자로 기본 주파수 판독 가능.

### M4 — 자함 동역학 + 싱글 플레이 (2~4일)
- 조타/트림/스로틀 → 방위각/수심/속도 모델 (아케이드 배제, 관성 있는 현실적 응답)
- RPM-속도 커플링 → 소음 모델 연동, 캐비테이션 모델(속도-선체)
- 스크립트 더미 타겟: 직진 + 회두 스크립트 (경로 웨이포인트)
- **완료 기준:** "탐지 → 조향 → 식별" 세션을 실제로 플레이할 수 있다.

### M5 — TMA + PDF 클라우드 (4~7일)
- 베어링-온리 파티클 필터 (상태: x,y,depth,vx,vy,vz, 등속 모델, N≈1000)
- 변침 레그(30~60°) 시 관측 기선 확보 → 필터 수렴
- PDF 클라우드 렌더: 2D 히스토그램 히트맵 (Canvas) → 이후 WebGPU 인광 셰이더
- 음영 구역/해저 차폐 영역에서 안개 실시간 절삭
- **완료 기준:** 변침 전 방위선 방향 수십 km 길쭉한 안개 → 변침 후 좁고 밝은 코어로 응축되는
  과정이 시각적으로 확인된다.

### M6 — 전술 레이어 (3~5일)
- 능동 핑: 탐지 + **자함 노출 페널티** (핑 직후 상대 BASS에 포착)
- 어뢰: 발사(발사음 노출), 유선 유도 기본 조종, 접근 경보
- 음향 기만기(디코이) 전개
- 시나리오 시스템: 해저 지형 + SVP 맵 2~3종, 승패 조건(어뢰 명중/시간 초과/노출)
- **완료 기준:** 스크립트 AI와 완전한 듀얼 루프(탐지→TMA→발사→회피) 플레이 가능.

### M7 — 코파일럿 & 폴리ッシュ (2~4일)
- Web Speech TTS + 300Hz~3.4kHz 대역통과 + 스퀠치 FX, 통신 로그(타임스탬프/화자 태그)
- VOICE/SUBTITLES 토글, ADVISORY LEVEL (CADET/OFFICER/SILENT)
- CRT 4종 테마 완성 (P31 Green / P13 Amber / Cyan / Night Red)
- 튜토리얼 시나리오
- **완료 기준:** CADET 레벨 안내를 켠 채 처음 플레이하는 사람이 M6 루프를 완주할 수 있다.

### M8 — 멀티플레이 (WebRTC) (3~5일)
- PeerJS 연결, 방 코드(예: `BLACKTIDE-7X9`) + 초대 링크, **SDP 텍스트 복사 폴백 모드**
- 2~5Hz `acousticState` 브로드캐스트 (WebRTC 문서의 JSON 페이로드 그대로)
- 이벤트 메시지: 능동 핑 / 어뢰 사출 / 디코이 전개 (즉시 전송)
- 상대 엔티티는 `importState()`로 주입 — **게임 코드는 1줄도 안 건드린다** (개발 지침 검증)
- **완료 기준:** 브라우저 두 대가 초대 코드로 접속해 M6 듀얼을 완료한다.

**총 예상: 약 23~36일 (1인 기준, 마일스톤 순서대로. Rust/WASM DSP 도입으로 M0/M2 증가분 반영).**

## 6. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| WebGPU 브라우저 지원 (Safari 등) | Canvas 2D가 기본 경로, WebGPU는 향상 옵션. M5에서 판단 |
| WASM DSP CPU 부하 (빔 수 × 엔티티 수) | Rust에서 SIMD(`std::arch`/`wide` 계열)로 빔포밍 커널 최적화, 엔티티 소음은 채널 믹다운으로 제한. M2에서 CPU 점유율 완료 기준으로 추적 |
| JS ↔ WASM 경계 오버헤드 | Float32Array를 링버퍼로 재사용(할당 0회), 파라미터는 Atomics/공유 버퍼로 전달. 매 샘플 콜백을 만들지 않음 |
| Rust→WASM 빌드 체인 초기 비용 | M0에서 wasm-pack + cargo watch 루프를 먼저 세우고, DSP 코어는 네이티브(cargo test)와 WASM을 같은 소스로 듀얼 빌드해 디버깅 부담 최소화 |
| 고증 vs 재미 괴리 | 물리 상수를 "고증 모드/아케이드 모드" 슬라이더로 분리해 튜닝 여지 확보 |
| 파티클 필터 발산/수렴 속도 튜닝 | 프로세스 노이즈 상수를 시나리오별 프리셋화, M5에서 충분한 시간 확보 |
| PeerJS 클라우드 시그널링 불안정 | SDP 복사/붙여넣기 서버리스 모드(설계 문서에 이미 포함)를 1급 기능으로 구현 |
| NAT 관통 실패 (P2P 미성립) | STUN 기본 제공, 실패 시 SDP 폴백 안내 UI |
