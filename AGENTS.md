# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Project

SSN-X Sonar Simulator — a browser-based (desktop-first) tactical submarine sonar game. No game server: multiplayer is WebRTC P2P (milestone M8). All design docs and code comments are in **Korean**; the master plan with milestones (M0–M8) and per-milestone completion criteria is `docs/개발 계획.md`. Physical constants live in `docs/물리 상수 시트.md` — it is the single source of truth (both peers must use identical constants for multiplayer sync), so keep Rust code and that sheet in agreement.

Stack: TypeScript (game/UI/sim) + **Rust** (all acoustic physics and audio synthesis, in the `dsp-core` crate). Vite + wasm-pack/cargo. 10 Hz fixed-timestep simulation with 60 fps interpolated rendering.

## Commands

```bash
npm run dev                 # Vite dev server (audio only works on localhost — see pitfalls)
npm run build               # tsc -b && vite build
npm test                    # vitest run (TS tests in tests/)
npx vitest run tests/acousticEntity.test.ts -t "name"   # single TS test
npm run wasm:test           # cargo test -p dsp-core (Rust tests run natively, not in WASM)
cargo test -p dsp-core <name>   # single Rust test (run from dsp-core/ or with -p)
npm run wasm:build          # wasm-pack build dsp-core --target web --out-dir pkg --dev  ← REQUIRED after any dsp-core change
npm run wasm:build:release  # release build (LTO, codegen-units=1)
```

`dsp-core/pkg/` is gitignored and regenerated by `npm run wasm:build` — if DSP changes don't seem to take effect in the browser, rebuild first, then suspect HTTP caching (see pitfalls).

Path aliases: `@/` → `src/`, `@dsp/` → `dsp-core/pkg/` (both Vite and tsconfig).

## Architecture

Two engines with a strict division of labor:

- **`dsp-core/` (Rust/WASM) — the only place audio is synthesized.** `src/lib.rs` exposes a stateful `DspEngine` via wasm-bindgen: `set_targets` / `set_ocean` / `set_beam` / `process`. Pipeline per sample block: target signals (tonal harmonics + DEMON-modulated cavitation broadband + Doppler) → per-hydrophone delays → full delay-and-sum beamforming (16-hydrophone spherical array, spec §3.2 `τᵢ = pᵢ·û/c`) → + Knudsen C₀ ocean noise → tanh soft clip. Modules: `physics/` (Thorp TL, Knudsen NL, sonar equations, thermocline), `noise/`, `source/`, `beamform/`.
  - Level convention: **200 µPa = 1.0 full scale (120 dB re 1µPa)**.
  - Rust coordinate frame: x=forward, y=down(depth), z=starboard. (The TS sim frame is different: x=east, depth +down, z=south — convert at the boundary.)
  - **`process()` must be called exactly once per audio block** — the engine is stateful (time accumulator, noise ring buffers). Calling it per channel makes time run N× faster. The host copies the mono output to all channels.
  - Target scene format: flat `Float32Array`, 8 floats per target: `[bearing_deg, range_m, depth_m, rpm, blades, tonal_db, cavitation, rel_vel_ms]`.
- **`src/dsp/worklets/sonarWorklet.ts` — thin WASM host** in an AudioWorklet. Web Audio API is deliberately auxiliary only (output path: gain/routing/post-filters like the comms radio FX); it never synthesizes.
- **`src/core/` — the game sim.** `AcousticEntity` (`entity/acousticEntity.ts`) is the single data structure for every sub/torpedo/decoy; the engine never knows who pilots it, and sensors/render/net consume only `AcousticEntity[]`. `exportState()`/`importState()` exist from day one as the M8 multiplayer payload (see `docs/WebRTC 기반 1_1 멀티플레이 구조.md`). `sim/tickLoop.ts` (accumulator pattern, 10 Hz) and `sim/world.ts` are the sim skeleton; as of M2 the tick callback is an empty placeholder for sub dynamics/target scripts/TMA.
- `src/main.ts` wires it together: start button → TickLoop + AudioContext; scene preset buttons post `{type:'scene'|'ocean'|'beam'}` messages to the worklet; an AnalyserNode measures output RMS for objective verification of scene changes.
- Planned `src/` subdirs (`audio/`, `game/`, `net/`, `render/`) are empty until their milestones (M3+).

## Pitfalls (learned the hard way)

- **WASM HTTP cache**: `pkg/dsp_core_bg.wasm` has a fixed filename, so a stale build sits in browser cache and physics edits appear not to apply. `main.ts` fetches it with `cache: 'no-cache'`; if you add other wasm consumers, do the same.
- **Chromium `WorkletGlobalScope` is bare**: no `fetch`/`URL`/`Response`/`TextDecoder` (and often no `performance`). Hence: `workletPolyfill.ts` must be imported **before** the wasm-pack glue (its top-level `new TextDecoder` would abort module evaluation), and wasm bytes are fetched on the main thread and transferred over the port via the `requestInit` handshake. CPU measurement falls back to `Date.now()` (~1 ms resolution) and reports a window-span upper bound, not per-block deltas.
- **Audio requires a secure context**: AudioContext won't start on non-localhost origins, and Vite 6 has no `--https` CLI flag — verify audio on localhost only.
- **TL units**: `transmission_loss_db` takes range in **meters** (spherical spreading `20·log10(R)` with R in meters; a km mistake inflates received level 1000× and everything clips at full scale).
- **CPU budget**: per-block DSP must stay under 5 ms (50 % of the 10 ms audio frame budget); the worklet reports this in the `cpu` HUD readout and it is an M2 completion criterion.
- Rust tests must stay deterministic (a test asserts identical output from two engines on the same scene) — this is a precondition for multiplayer sync.
